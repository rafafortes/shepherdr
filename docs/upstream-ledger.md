# Upstream ledger

Every improvement upstream (eliasstravik/shepherdr) did after `v2.0.0`, the release our line `herdr-tui` starts from,
weighed against the criteria in [docs/upstream.md](upstream.md). One row per improvement; related commits are one row.
Verdicts are `adopt` (fits 2.0's code as it is), `port` (the idea, rewritten against 2.0's code) or `skip`, always with
the reason. Size: **S** a small change (one area, a day's work at most, tests included), **M** a few files and a
session's work, **L** a subsystem or a rewrite.

tag `v3.1.28` (`9cc43dca`), branch `v2.0` at `ebb17d58` (unchanged). Four passes so far: the first read to `main`'s tip
`dc1b6782`, one commit past where the tag `v3.1.3` points (`dc018f2a`); the second read 3.1.4 to 3.1.10; the third read
3.1.11 to 3.1.14; this one reads 3.1.15 to 3.1.28, one commit past the newest tag to `main`'s tip, the sections below.

## The `v2.0` line: merged whole in [PR #2](https://github.com/rafafortes/shepherdr/pull/2) (SHE-2)

This is the closest code to ours: every commit here is a descendant of `v2.0.0`, so they apply to `herdr-tui` in order
(the first is `9c0e22ff`). They were never released as 2.0.x: they sit on upstream `main` as ancestors of 2.1.0, under
the herdr-core rewrite. The operator chose to take the line whole rather than port it row by row, so SHE-2 merged
`bcaa2ca4` (this line's SHE-296, its 41st commit) into `herdr-tui` as a real merge: upstream's commits are ancestors of
our branch, so the next intake pass sees them as done. `ebb17d58` (SHE-295, the bubblewrap-sandboxed coordinator
Autopilot) stays out, as the row below says. Every row's verdict below is therefore `adopted (merged in #2)` unless it
says otherwise; the reasons are kept as the record of what each row brings and what it costs us.

**Their CI was red, and that mattered.** At the tip (`ebb17d58`) run
[40916895905](https://github.com/eliasstravik/shepherdr/actions/runs/40916895905): types and build passed, all three
test shards failed, 48 named tests among them, most of them browser/layout suites (`unified search`, `a place's
Autopilot`, `the lists' chips`, `restarting an agent`, `the UI pass`), plus non-UI ones such as `claude reader` and
`a long chat log`. Upstream `main` pointed at `bcaa2ca4` (this line's SHE-296) when its own run 40906888093 failed as
well, and `ebb17d58`'s own facts say so: "GitHub full check remains red on pre-existing main failures". We read the
cause as the workflow running on pushes to `main` only, so tests a commit brought first ran after merging, and this
line's UI churn left them stale. The 2.1 rewrite replaced that code and its suite, and `main` has been green again
since 2026-11-04. SHE-2 made the suite green on our branch: the stale tests follow the merged code (the newer
chat-agent rule, unified search's second menu item, the + popup's agent controls and its restart sheet, the attention
badge's split label, a task row's base branch, the Everything list at the main home space, and the pane reads the app
now makes after a look at herdr), and a pending herdr launch is no longer taken for a stopped agent. The release
commits themselves (tags, changelogs) get no row.

## 2.1.0 and 2.1.1: the herdr-core rewrite and its fixes

**`v2.1.0`** (`d1cda048`, 193 commits) is a rewrite, not an update: it runs on **herdr-core** 0.1.14, logs in only
through **Tailscale** (`Tailscale-User-Login` plus a tailnet Host, or a token on `127.0.0.1` with no `Origin`), starts
only **Claude Code and Codex**, and keeps its data in a fresh `~/.shepherdr` with no import. **skip** as a whole: all
four criteria fail (no terminal plugin, their login, no pi, a new data home); the analysis was done when 3.1.3
appeared and is summarised here.

**`v2.1.1`** (`de8e1795` SHEP-1 #581 plus 41 fixes) restores `herdr-plugin.toml` and changes the plugin id to
`shepherdr` **on purpose**: herdr refuses an update whose id changed, so `herdr plugin update` can never move a 2.0
install onto the rewrite. Our rule follows from it: the id `herdr-projects` never changes in our line.

## Not from upstream: the Models summary, its warnings and the usage ledger, built here

Checked 2026-11-13 against upstream `main` (3.x line) and `v2.0` (fetched that day): `git grep` for run-out, "out of
allowance", 402, credit, usage ledger and per-model usage in both lines' code, `git log -i` for usage, quota and limit,
and the public issues with "usage limit quota" (`gh issue list`, none matched). Upstream counts no model's calls per
provider and remembers no run-out; what it has is plan limits, and an insights add-on that counts how the person uses the
screens. Taken and turned down, from those:

- **Taken: the window of a plan limit, and that a refilled window says nothing of now** (`3a3ce931`, #553 "plan usage
  limits"): the quota slot is a list of windows with a used share, a count and a refill time, and the summary leaves out a
  window whose refill is past. Its reads came in the next step (see the next bullets).
- **Turned down: the usage insights add-on** (`181d3568`, SHEP-100): it records screens, features and time on them for the
  person, on their own machines; it is not a count of the model calls, and its architecture (`mods/`, `service/`) is not
  2.0's. Nothing from it is in this line.
- **Ours: the per-provider ledger** (`usage-ledger.ts`, `usage-feed.ts`): each model call counted once per chat by its own
  id, from the logs of Shepherdr's agents only, with the run-outs (retry.ts: allowance, credit, the 402) and the alert once
  per run of them. See [settings](settings.md#summary).
- **Ported, the idea of Claude Code's plan-limit read** (`3a3ce931` and `c0ee1971`, #553 and #561, read only; `helper/core-plan-limits.ts`):
  one `claude -p /usage` process per read, sealed (bubblewrap with the root read-only and a throwaway `/tmp`), niced, 60 s
  limit, `TZ=UTC` for the reset words; a login near its renewal is not read, since a sealed run cannot save a renewed login.
  Ported to this code as `server/live/plan-limits.ts`, and without bubblewrap nothing is read. Not ported: Codex's
  rate-limit read (Codex is not on this host) and upstream's Mac seal (`sandbox-exec`, a Linux desktop here). See
  [settings](settings.md#quotas).
- **Ported with attribution, the Command Code account read** (MIT License, Copyright (c) 2025 Pat Woz,
  `pi-commandcode-provider` `src/quota.ts`, read in its installed package): `whoami` and the credits, with the key from
  Shepherdr's own Secrets (`COMMANDCODE_API_KEY`), in `server/live/command-code-quota.ts` (the credit's and the windows'
  reading, the 15 s deadline). The package's usage summary and subscription are not read.
- **Ours: OpenCode Go's estimate and its learned limit, and the quota scheduler and alerts**: OpenCode has no read of its
  quota, so the ledger's own tokens and cost per window, and the lowest limit its run-outs show (`quota-estimate.ts`); the
  reads every ten minutes, Refresh quotas and each window's alert once (`quotas.ts`).
